The Palitra Tag is a small JavaScript snippet you put on your website. It gives each visitor a
persistent ID, captures the traffic source (the Palitra Linker, UTM parameters or the referrer),
sends page views on its own and lets you send your own events, such as purchases. That is how
Palitra links on-site visits and conversions to ad spend.

Every project member can open the "Palitra Tag" screen. It holds the code to install and
statistics on what the tag has sent so far.

## Open the screen

1. Pick the project in the sidebar and go to "Data" — the "Data Pipeline" page opens.
2. In "Data Sources", find the "Tag" card and click "Configure".

The "Tag" card already shows the tag's status — "Receiving data", "Idle" or "Not configured" —
and the number of events today or the time of the last event.

## Install the tag on your site

1. In the "Installation" block, find "Step 1: Add the base snippet".
2. Click "Copy" in the top right corner of the code block. The button changes to "Copied" for two
   seconds.
3. Paste the code before the closing `</head>` tag on every page of the site.
4. Publish the change on your site and open any of its pages.

Copy the code from the screen, not from this article: it carries your project's token and the
addresses of your Palitra installation. It looks like this:

```html
<script>
  (function(w,d,s){ /* loads the tag asynchronously */ })(window,document,'palitra');
  palitra('init', '<project token>', { endpoint: '<event ingest address>' });
</script>
```

The tag sends page views (`page_view`) by itself — nothing else is needed for that.

## Pass user logins

Step 2 on the screen is marked "Optional". Call `identify` after a user logs in to your site and
pass their ID from your system:

```js
palitra('identify', currentUser.id);
```

This links the visitor's anonymous sessions to a real user, for example for CRM matching.

## Send your own events

Step 3, also "Optional". To send a conversion or another event, call `event` with the event name
and its parameters:

```js
palitra('event', 'purchase', {
  value: 5900,
  currency: 'RUB',
  transaction_id: 'ORD-123',
  items: [{ id: 'SKU-1', price: 5900, quantity: 1 }]
});
```

For Palitra to count the event as a conversion, mark it as one in the [events](/data/events/)
registry.

## Link IDs from other analytics systems

Step 4, "Optional". Web analytics IDs are linked to the Palitra visitor automatically when you
connect the matching [connector](/connectors/overview/). For any other external ID, call `link`:

```js
palitra('link', 'id_type', 'id_value');
```

The ID type uses lowercase Latin letters, digits and underscores and starts with a letter, such as
`ga4_client_id`.

## Check that data arrives

After installing, open any page of your site and return to the "Palitra Tag" screen. The status in
the top right corner refreshes by itself every 30 seconds.

| Status | Meaning |
| --- | --- |
| "Receiving data" | The last event arrived within the past 15 minutes. |
| "Idle" | Events arrived before, but none in the past 15 minutes. |
| "Not receiving" | The tag hasn't sent a single event yet. |

Under the status are four counters: "Events today", "Total events", "Identified users" and
"Anonymous users". The bottom of the screen shows the last event: "Last event received: …" or "No
events received yet.".

If the status stays "Not receiving" after you opened a page of your site, check that the code is
on that page inside `<head>` and that the change to the site is published.

## What the tag collects

The "What the tag collects" block lists the data the tag sends to Palitra:

| Field | What it is |
| --- | --- |
| `palitra_id` | A persistent visitor ID. |
| `session_id` | A session ID used to group events into visits. |
| `client_user_id` | The user ID from your system, after an `identify` call. |
| "Traffic source" | The Palitra Linker, UTM parameters or the referrer. |
| "Events" | `page_view` automatically, plus your events sent with `event`. |
| `linked_ids` | Analytics system IDs: from connectors and passed with `link`. |

The Palitra Linker is a parameter in ad links. How a connector adds it is described under
"Auto-tagging" in the [Yandex Direct](/connectors/yandex-direct/) article.

## Errors

- "Failed to load tag configuration" — the screen didn't receive the install code. Click "Retry".
- "Could not load status" next to the status, or "Status unavailable." at the bottom — the
  statistics didn't load; the install code is still shown. Click "Retry" next to the status.
