Единый вход (SSO) позволяет сотрудникам входить в Палитру через корпоративного провайдера
удостоверений (IdP) — например Okta, Azure AD, Google Workspace, Keycloak. Поддерживаются
протоколы SAML 2.0 и OpenID Connect (OIDC). У организации может быть одно подключение SSO.

Вкладку «Единый вход» видит и настраивает только владелец организации. Администраторы этой
вкладки не видят.

Единый вход входит в тариф Enterprise. Если на вашем тарифе доступно дополнение
«SSO / SAML», его можно подключить. Если ни того, ни другого нет, вместо настроек вы увидите
«SSO / SAML не входит в ваш тариф» с кнопками «Купить дополнение» и «Повысить тариф». Обе
ведут на вкладку «Биллинг» — см. [Биллинг](/organization/billing/).

## Как открыть вкладку

1. Нажмите на своё имя внизу боковой панели и выберите «Настройки организации».
2. Перейдите на вкладку «Единый вход».

Пока подключения нет, на вкладке написано «Вход через корпоративного провайдера удостоверений.
Поддерживаются SAML 2.0 и OIDC.» и есть кнопка «Настроить SSO».

## Настроить SSO

Нажмите «Настроить SSO» — откроется мастер «Настройка единого входа» из шести шагов. Вверху
показан номер шага, например «Шаг 1 из 6». Переходите дальше кнопкой «Продолжить», назад —
кнопкой «Назад». Мастер не пустит дальше, пока на шаге не заполнены обязательные поля.

Держите под рукой консоль администратора вашего IdP: часть данных нужно взять оттуда, а часть
— передать туда из Палитры.

/>

### Шаг 1. Протокол

1. Выберите «Протокол»: «SAML 2.0» или «OpenID Connect (OIDC)».
2. Введите «Название подключения», например `Acme Corp SSO` — до 100 символов. Это имя
   показывается в Палитре, например в окне приглашения на вкладке «Участники».

Протокол потом изменить нельзя: при редактировании мастер начинается со второго шага. Чтобы
сменить протокол, удалите подключение и создайте новое.

### Шаг 2. Данные провайдера

Заполните поля из настроек приложения в вашем IdP.

Для SAML 2.0:

- «Entity ID провайдера»
- «SSO URL провайдера»
- «Сертификат X.509» — сертификат подписи IdP.
- «Формат Name ID» — необязательно, например
  `urn:oasis:names:tc:SAML:1.1:nameid-format:emailAddress`.

Для OIDC:

- «URL издателя» (issuer)
- «Client ID»
- «Client Secret» — «Хранится в зашифрованном виде. Никогда не возвращается в ответах API.»

### Шаг 3. Email-домены

В поле «Разрешённые email-домены» добавьте домены почты вашей компании, например `acme.com`.
Введите домен и нажмите Enter или запятую; так можно добавить несколько доменов. Нужен хотя бы
один.

По этим доменам Палитра определяет, к кому относится принудительный вход через SSO (см.
[Принудительный SSO](#принудительный-sso)).

Каждый домен может принадлежать только одной организации в Палитре. Ошибки на этом шаге:

- «Некорректный домен. Используйте формат: example.com» — домен написан с ошибкой, например с
  `@` в начале.
- «Этот домен уже занят другой организацией.» — домен уже указан в подключении SSO другой
  организации.

### Шаг 4. Роли

Здесь задаётся, какую роль в организации получает человек, который входит через SSO.

- «Роль по умолчанию» — «Владелец», «Администратор» или «Участник». По умолчанию —
  «Участник».
- «Атрибут роли» — необязательно. Имя атрибута (claim) из ответа IdP, по которому определяется
  роль, например `groups`.
- «Сопоставление ролей» — таблица «Значение атрибута» → «Роль». Строки добавляются кнопкой
  «Добавить сопоставление», удаляются кнопкой «Удалить строку».

Если значение атрибута у пользователя совпадает со строкой таблицы, он получает роль из этой
строки, иначе — роль по умолчанию. Если атрибут роли задан, роль пересчитывается при каждом
входе через SSO: изменённая вручную на вкладке «Участники» роль будет перезаписана при следующем
входе.

### Шаг 5. Настройки

- «Включить SSO» — включено по умолчанию. Выключите, чтобы остановить SSO, не удаляя
  настройки.
- «Принудительный SSO» — выключено по умолчанию. Когда включено, участники должны входить
  через SSO. Владельцы и участники с обходом SSO по-прежнему могут входить по паролю.

### Шаг 6. Проверка

Мастер покажет все введённые данные по разделам «Основное», «Роли», «Настройки» и «Метаданные
поставщика услуг». Метаданные Палитры (Entity ID, файл метаданных) появятся после сохранения:
рядом стоит «Доступно после сохранения.».

Нажмите «Сохранить». После сохранения на вкладке появится карточка подключения.

### Если сохранить не удалось

- «Один или несколько доменов электронной почты уже используются другой организацией.» —
  мастер вернётся на шаг 3 и отметит занятые домены. Уберите их и сохраните снова.
- «Конфигурация IdP недействительна. Проверьте настройки и попробуйте снова.» — мастер
  вернётся на шаг 2. Сверьте данные с консолью IdP.
- «Что-то пошло не так. Попробуйте снова.» — повторите сохранение позже.

## Передать данные Палитры в IdP

Чтобы IdP принимал вход в Палитру, в нём нужно указать адреса Палитры. Они есть на карточке
подключения, в разделе «Метаданные поставщика услуг»:

- для SAML — «ACS URL» и файл метаданных: нажмите «Скачать метаданные» и импортируйте файл в
  IdP;
- для OIDC — «Redirect URI»: добавьте его в разрешённые адреса перенаправления приложения в
  IdP.

## Карточка подключения

После настройки на вкладке показана карточка с названием подключения, протоколом («SAML» или
«OIDC») и отметкой «Активно» или «Неактивно». На карточке:

- «URL для входа» — адрес вида `https://…/orgs/<идентификатор>/login`. Кнопки «Скопировать» и
  «Открыть в новой вкладке». «Поделитесь этим URL с командой, чтобы они могли войти через
  SSO.»
- «Почтовые домены» — домены из шага 3.
- «Роль по умолчанию», «Клейм роли» и «Сопоставление ролей» — настройки из шага 4.
- «Управление доступом» — переключатели «Включено» и «Принудительно». Они меняют настройку
  сразу, без мастера. Если не получилось — «Не удалось обновить настройку. Попробуйте ещё
  раз.».
- «Метаданные поставщика услуг» — данные для IdP (см. выше).
- «Диагностика» — проверка подключения.

Идентификатор в URL для входа — это «URL-идентификатор» организации со вкладки
[Общие](/organization/general/). Если его изменить, адрес для входа тоже изменится.

## Проверить подключение

1. На карточке, в разделе «Диагностика», нажмите «Запустить диагностику».
2. Если всё в порядке, появится «Конфигурация доступна».
3. Если нет — список «Ошибки диагностики». Исправьте настройки через «Редактировать».

## Как входят участники

Поделитесь с командой URL для входа. Человек открывает его, входит у вашего IdP и попадает в
Палитру.

При первом входе через SSO Палитра сама создаёт учётную запись, если её ещё нет, и добавляет
человека в организацию с ролью по правилам шага 4. Отдельно приглашать его не нужно.

Если вы приглашаете людей вручную, в окне приглашения на вкладке «Участники» будет напоминание
«В этой организации используется SSO (…)». См. [Участники](/organization/members/).

## Принудительный SSO

Когда включено «Принудительно», участник организации, чья почта на одном из доменов
подключения, не сможет войти по паролю — только через SSO. Исключения:

- владелец организации — всегда может войти по паролю, чтобы не потерять доступ, если IdP
  недоступен;
- участники с обходом SSO. Владелец выдаёт обход на вкладке «Участники»: «Разрешить обход SSO» в
  меню участника. Подробнее — в статье [Участники](/organization/members/#обход-sso).

Перед включением проверьте подключение диагностикой и убедитесь, что вход через SSO работает.

## Изменить подключение

1. На карточке нажмите «Редактировать».
2. Откроется мастер «Редактировать конфигурацию SSO» со второго шага: протокол изменить нельзя.
3. Введите данные IdP заново: «Введите учётные данные IdP повторно. Секреты не возвращаются
   сервером и должны быть указаны снова.»
4. Пройдите шаги и нажмите «Сохранить».

## Удалить подключение

1. На карточке нажмите «Удалить подключение».
2. Подтвердите в окне «Удалить SSO-подключение?» кнопкой «Удалить».

SSO для организации отключится. Пользователи, которые входили только через SSO, потеряют
доступ, если у них не включён обход SSO. Если удалить не удалось — «Не удалось удалить
SSO-подключение. Попробуйте ещё раз.».

## Ошибки загрузки

«Не удалось загрузить конфигурацию SSO. Попробуйте снова.» — обновите страницу.
