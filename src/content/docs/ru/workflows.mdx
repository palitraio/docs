Воркфлоу — это сценарий, который Палитра выполняет сама: по событию в проекте, по вызову
вебхука или по кнопке. Сценарий собирается в визуальном редакторе из шагов (нод):
триггер запускает воркфлоу, дальше идут шаги с данными, вызовами агента, действиями в
рекламных кабинетах, уведомлениями и согласованиями. Каждый запуск сохраняется в истории: видно,
какие шаги выполнились, что они вернули и где произошла ошибка.

Раздел видят все участники проекта. Создавать, менять, запускать, включать и удалять воркфлоу
могут менеджеры проекта, а также владелец и администратор организации. Остальные участники
открывают воркфлоу только для просмотра: редактор показывает схему и настройки шагов, но не даёт
их менять.

Воркфлоу доступны не на всех тарифах. Если они не входят в тариф организации, вместо списка вы
увидите «Воркфлоу не входят в ваш тариф» и кнопку «Повысить тариф». Число запусков в месяц тоже
ограничено тарифом — подробнее в разделе [Ошибки и что делать](#ошибки-и-что-делать).

## Как открыть раздел

1. В боковой панели выберите проект в списке проектов.
2. Нажмите «Воркфлоу».

Вверху раздела две вкладки: «Воркфлоу» — список сценариев проекта, и «История запусков» —
последние запуски всех воркфлоу проекта.

## Список воркфлоу

В таблице четыре колонки:

- «Название» — название воркфлоу. Нажмите на него, чтобы открыть редактор.
- «Триггеры» — значки триггеров воркфлоу. Наведите на значок, чтобы увидеть подпись: «По
  расписанию», «По событию», «По вебхуку», «По требованию» или «Вызов из другого процесса».
  Если триггера нет, в колонке написано «Без триггера».
- «Последний запуск» — сколько времени прошло с последнего запуска, или «Ещё не запускался».
- «Действия» — меню с действиями над воркфлоу.

Цветная точка перед названием показывает состояние воркфлоу:

| Цвет | Что значит |
| --- | --- |
| Красный | Последний запуск завершился ошибкой. |
| Жёлтый | Последний запуск ждёт согласования. |
| Зелёный | Воркфлоу включён, у него есть триггер помимо «Вручную», и последний запуск прошёл без ошибок. |
| Серый | Всё остальное: воркфлоу выключен, запускается только вручную или ещё не запускался. |

В меню «Действия» есть:

- «Включить» или «Выключить» — только для воркфлоу, у которых есть триггер помимо «Вручную».
  Подробнее — в разделе [Включить и выключить](#включить-и-выключить).
- «Настроить» — открывает редактор.
- «Запустить» — запускает воркфлоу сразу. Пункт есть, только если у воркфлоу ровно один
  триггер; воркфлоу с несколькими триггерами запускайте из редактора.
- «Удалить» — удаляет воркфлоу.

Если в проекте ещё нет воркфлоу, вместо таблицы написано «Пока нет воркфлоу».

## Создать воркфлоу

1. Нажмите «Новый воркфлоу».
2. Откроется пустой редактор с названием «Новый воркфлоу». Нажмите на название вверху и введите
   своё.
3. Добавьте триггер: перетащите его из панели «Ноды» слева на холст. Пока триггера нет, в панели
   доступны только триггеры и заметки, а у остальных нод подсказка «Сначала добавьте триггер».
4. Добавьте следующие шаги и соедините их: потяните от точки внизу одного шага к точке вверху
   следующего.
5. Настройте каждый шаг — дважды кликните по нему.
6. Нажмите «Сохранить».

Новый воркфлоу появляется в списке только после первого сохранения. Если уйти из редактора, не
сохранив его, ничего не создастся.

<Screenshot id="workflows-editor" alt="Редактор воркфлоу: панель «Ноды» слева, шаги на холсте и кнопки «Сохранить» и «Запустить»" />

## Редактор: шаги и холст

Шаги добавляются на холст несколькими способами:

- перетащите ноду из панели «Ноды» или дважды кликните по ней — она появится в центре холста;
- нажмите `Tab` или выберите «Добавить ноду» в меню правой кнопки мыши на пустом месте холста —
  откроется поиск нод;
- `Shift+S` или «Добавить заметку» добавляют заметку. Заметки — это подписи на холсте, их нельзя
  соединять с шагами.

Ноды в панели «Ноды» разбиты на группы:

| Группа | Ноды |
| --- | --- |
| «Триггеры» | «Расписание», «Вручную», «Событие», «Вебхук», «Другой воркфлоу» |
| «ИИ» | «Навык», «Вызов агента», «Генерация изображений» |
| «Коннекторы» | «Источник данных», «Действие коннектора», «Запись данных» |
| «Преобразование данных» | «Задать значения», «Фильтр», «Ограничение», «Удалить дубликаты», «Разделить», «Агрегация», «Сводка», «Переименовать ключи», «Сортировка», «Объединить», «Дата и время» |
| «Логика потока» | «Условие», «Переключатель», «Сравнить», «Цикл», «Задержка», «Подпроцесс», «Стоп с ошибкой» |
| «Базовые» | «HTTP-запрос», «Скрипт», «Экспорт файла» |
| «Проверка человеком» | «Уведомление», «Согласование» |
| «Документация» | «Заметка» |

Правой кнопкой мыши по шагу открывается меню: «Выполнить шаг», «Выполнить отсюда»,
«Настроить», «Переименовать», «Деактивировать» (или «Активировать»), «Копировать»,
«Дублировать», «Упорядочить воркфлоу» и «Удалить». Выделенные шаги удаляются клавишами
`Delete` и `Backspace`.

Деактивированный шаг остаётся на схеме, но при запуске пропускается и передаёт свои входные данные
дальше без изменений. На холсте он и шаги, до которых можно дойти только через него, становятся
бледными. Будьте осторожны с шагом «Согласование»: деактивированный, он не останавливает
запуск и пропускает действия дальше так, будто их одобрили.

Горячие клавиши (работают у тех, кто может менять воркфлоу):

| Клавиши | Действие |
| --- | --- |
| `Ctrl+C` / `⌘C` | Копировать выделенные шаги |
| `Ctrl+V` / `⌘V` | Вставить |
| `Ctrl+D` / `⌘D` | Дублировать |
| `Ctrl+A` / `⌘A` | Выделить всё |
| `Shift+Alt+T` | Упорядочить воркфлоу |
| `Tab` | Добавить ноду |
| `Shift+S` | Добавить заметку |

## Настроить шаг

Дважды кликните по шагу, чтобы открыть его настройки. Название шага можно поменять в поле
«Название». Настройки разделены на две вкладки.

**«Параметры»** — то, что делает шаг: например, какую таблицу читать или какое сообщение
отправить. Набор полей зависит от типа ноды. У многих полей можно выбрать режим «Фиксированное»
(обычное значение) или «Выражение» — тогда значение подставляется из данных предыдущих шагов.
Выражение пишется в двойных фигурных скобках `{{ }}` и должно ссылаться на `$json`, `$node`,
`$now`, `$runId`, `$items` или `$trigger`.

**«Настройки»** — поведение шага:

- «Заметки» — комментарий к шагу.
- «При ошибке» — что делать, если шаг завершился ошибкой: «Остановить воркфлоу», «Продолжить»
  или «Продолжить с выводом ошибки».
- «Повтор при ошибке» — повторить шаг, если он упал. По умолчанию «Макс. количество попыток» —
  3, «Пауза между попытками (мс)» — 5000.

Рядом с параметрами показаны панели «Вход» и «Выход»: какие данные шаг получил от предыдущего
шага и что он вернул. Чтобы проверить шаг, не запуская весь воркфлоу, нажмите «Выполнить шаг».
Если у предыдущих шагов ещё нет данных, Палитра предложит «Выполнить предыдущие узлы» или задать
тестовые данные вручную («или задать тестовые данные»). Тестовые данные вводятся в формате JSON.

<Screenshot id="workflows-node-config" alt="Окно настройки шага с вкладками «Параметры» и «Настройки» и панелями «Вход» и «Выход»" />

Участники без права менять воркфлоу видят это окно только для чтения.

## Триггеры

Триггер — первый шаг воркфлоу, он определяет, когда воркфлоу запускается. Без триггера воркфлоу
нельзя сохранить. Триггеров может быть несколько, но каждый запуск начинается с одного из них.

| Триггер | Когда запускает воркфлоу |
| --- | --- |
| «Вручную» | По кнопке «Запустить». У этого триггера нет настроек. В воркфлоу может быть только один такой триггер. |
| «Расписание» | Настраивается интервалом или cron-выражением, см. [Расписание](#расписание). |
| «Событие» | Когда в проекте происходит выбранное событие. |
| «Вебхук» | Когда внешняя система вызывает адрес вебхука. |
| «Другой воркфлоу» | Когда этот воркфлоу вызывает другой воркфлоу через шаг «Подпроцесс». Такой триггер может быть только один. |

Триггеры «Событие» и «Вебхук» срабатывают, только пока воркфлоу включён. Ручной
запуск работает и у выключенного воркфлоу.

### Расписание

В настройках задаётся одно или несколько правил («+ Добавить правило»). В каждом правиле
выберите «Интервал запуска» — «Секунды», «Минуты», «Часы», «Дни», «Недели», «Месяцы» — и
укажите число в поле «Каждые». Для произвольного расписания выберите «Cron (вручную)» и введите
«Cron-выражение», например `0 9 * * 1-5`.

### Событие

Выберите «Тип события»:

- «Workflow завершён»
- «Обнаружена аномалия (KPI)»
- «Синхронизация коннектора завершена»
- «Изменился статус коннектора»
- «Медиаплан обновлён»

В поле «Фильтр-выражение» можно сузить условие, например `$event.metric == spend`. Без фильтра
воркфлоу запускается на каждое событие выбранного типа. Поля события видны в панели «Выход»
триггера; обращайтесь к ним как `$event.<поле>`.

### Вебхук

- «HTTP-метод» — `GET`, `POST`, `PUT` или `DELETE`.
- «Путь» — часть адреса вебхука. Пути `config`, `rotate`, `status`, `events` и `test`
  зарезервированы. Путь не должен совпадать с путём вебхука другого воркфлоу.
- «Аутентификация» — «Нет», «Basic Auth» (имя пользователя и пароль) или «Header Auth» (имя и
  значение заголовка).
- «Код ответа» — HTTP-код, который получит вызывающая система.
- «Отвечать» — «Сразу» или «После завершения последнего узла».

Продакшн-адрес вебхука принимает события только пока воркфлоу включён. Чтобы проверить вебхук
до включения, нажмите «Слушать тестовое событие»: Палитра покажет тестовый адрес («Скопировать
URL») и таймер «Осталось: …». Отправьте на этот адрес запрос — появится «Событие получено», и
данные запроса попадут в панель «Выход». Если запрос не пришёл вовремя, вы увидите «События не
получены — попробуйте снова».

### Другой воркфлоу

Выберите «Режим ввода»: «Задать поля» — перечислите входные поля с типами (имена в `snake_case`,
например `campaign_id`), или «Произвольный объект» — воркфлоу примет любой объект. Затем в
другом воркфлоу добавьте шаг «Подпроцесс», выберите этот воркфлоу в поле «Workflow» и заполните
«Входные данные workflow».

## Согласование и уведомления

Шаг **«Согласование»** ставит запуск на паузу, пока человек не примет решение. Запуск получает
статус «Ожидает подтверждения», а в списке воркфлоу точка становится жёлтой. Решение принимается
на [странице запуска](#страница-запуска), в панели логов редактора, если запуск идёт оттуда, или
в окне «Уведомления» в приложении. Решать могут менеджеры проекта, а также владелец и
администратор организации.

По каждому предложенному действию доступны кнопки:

- «Одобрить» — выполнить действие как предложено;
- «Изменить» — поправить параметры действия в поле «Изменённые параметры (JSON)», затем
  «Одобрить с изменениями»;
- «Отклонить» — не выполнять.

К решению можно добавить комментарий. Если хотя бы одно действие отклонено, шаги после
согласования не выполняются — даже для одобренных действий. Рядом с действием может стоять
«вероятность успеха», а под ним — «Предупреждение guardrail».

В настройке «При истечении таймаута» выбирается, что произойдёт, если никто не принял решение:
«Отклонить всё», «Одобрить всё» или «Завершить workflow с ошибкой».

Шаг **«Уведомление»** отправляет сообщение. Выберите «Тип канала» — Telegram, Slack или Email,
«Получатель» и напишите «Сообщение». Для Telegram и Slack получатель выбирается из каналов,
подключённых к проекту.

## Действия в кабинетах: тестовый и боевой режим

Шаг «Действие коннектора» выполняет действие подключённого коннектора, например меняет ставку в
рекламном кабинете. В поле «Режим» выберите:

- «Тестовый прогон» — значение по умолчанию. Действия, которые что-то меняют, не применяются;
  действия чтения возвращают настоящие данные.
- «Боевой» — изменения применяются в кабинете.

Перед боевыми действиями удобно поставить шаг «Согласование», чтобы человек проверял их до
выполнения.

## Сохранить воркфлоу

Нажмите «Сохранить». Кнопка активна, только когда есть несохранённые изменения и у воркфлоу есть
название. Если уйти со страницы с несохранёнными изменениями, Палитра спросит: «У вас есть
несохранённые изменения. Покинуть страницу без сохранения?» — выберите «Покинуть без сохранения»
или «Отмена».

Перед сохранением Палитра проверяет схему. Если что-то не так, появится сообщение, а шаг или
соединение с ошибкой будут выделены на холсте. Частые сообщения:

- «Добавьте trigger-ноду перед сохранением — она нужна каждому воркфлоу.»
- «В воркфлоу неожиданный цикл — шаг соединён с более ранним.» — уберите соединение, которое
  ведёт назад. Повторять шаги можно нодой «Цикл».
- «Ноде Loop нужно соединение от тела обратно в цикл.» и «Подключите выход «Done» ноды Loop к
  следующему шагу.» — достройте соединения у ноды «Цикл».
- «Стикеры нельзя соединять — удалите ребро на заметке.»
- «Соединение ссылается на несуществующую ноду — удалите его и создайте заново.»
- «Зарезервированный путь вебхука» — смените «Путь» у вебхука.
- «Выберите поддерживаемый тип события для триггера «Событие».»
- Сообщения про «Другой воркфлоу» и «Подпроцесс» — например, «Это создаст цикл подпроцессов —
  workflow не может вызывать сам себя прямо или косвенно.»

Если сообщение общее — «Не удалось сохранить воркфлоу», — проверьте выражения в параметрах шагов
и уникальность пути вебхука.

## Включить и выключить

Новый воркфлоу сохраняется выключенным. Чтобы триггеры «Событие» и «Вебхук» начали
срабатывать:

1. Откройте вкладку «Воркфлоу».
2. В строке воркфлоу откройте меню «Действия».
3. Выберите «Включить».

«Выключить» в том же меню останавливает автоматические запуски. У воркфлоу, где есть только
триггер «Вручную», этих пунктов нет. Если переключить не удалось, появится «Не удалось обновить
воркфлоу».

## Запустить воркфлоу

**Из списка.** В меню «Действия» выберите «Запустить». Появится «Запуск начат». Пункт доступен,
только если у воркфлоу один триггер.

**Из редактора.**

1. Нажмите «Запустить». Если в воркфлоу несколько триггеров, выберите в меню «Запустить с
   триггера», с какого начать.
2. Палитра сначала сохранит воркфлоу, затем запустит его и покажет «Запуск воркфлоу начат».
3. Внизу откроется панель логов: шаги по мере выполнения, их статус и длительность. Нажмите на
   шаг, чтобы увидеть его результат.
4. Чтобы открыть полную страницу запуска, нажмите «Открыть запуск».

Пока на холсте нет триггера, рядом с названием написано «Добавьте триггер, прежде чем запускать
этот воркфлоу.». «Очистить выполнение» в панели логов убирает результаты последнего запуска с
холста.

**Отладочные запуски.** Пункт «Выполнить отсюда» в меню шага (или кнопка в его настройках)
запускает воркфлоу с этого шага, используя данные предыдущих шагов из прошлых запусков. Такой
запуск не попадает в историю, не расходует месячный лимит запусков, а действия коннекторов в нём
не применяют изменения. «Выполнить шаг» проверяет только один шаг.

Каждый обычный запуск — по кнопке, событию или вебхуку — расходует месячный лимит
запусков тарифа.

## История запусков

На вкладке «История запусков» — последние 20 запусков всех воркфлоу проекта. В таблице колонки
«Дата», «Время», «Воркфлоу» и «Статус». Нажмите на строку, чтобы открыть страницу запуска.

Запуски удалённого воркфлоу остаются в истории с подписью «(удалённый воркфлоу)» и тоже
открываются.

## Страница запуска

Вверху — заголовок «Запуск: дата — название воркфлоу», триггер, с которого начался запуск
(«Триггер: …»), и статус запуска. Под ним — «Длительность», «Шагов», «Начало» и «Завершение».
Пока запуск идёт, страница обновляется сама.

Если запуск завершился ошибкой, над шагами появится блок «Запуск завершился с ошибкой» с
описанием причины.

Слева — «Хронология»: шаги запуска по порядку, со статусом и длительностью. Справа две вкладки:

- «Вывод» — результат шага, выбранного в хронологии. При открытии выбран первый шаг с ошибкой,
  а если ошибок нет — последний шаг. Для упавшего шага показан блок «Шаг завершился с ошибкой».
- «Уведомления» — сообщения и согласования этого запуска. Если запуск ждёт решения, страница
  открывается сразу на этой вкладке. Если уведомлений не было, написано «Этот запуск не создал
  уведомлений».

У удалённого воркфлоу несогласованные действия не показываются: принять по ним решение уже
нельзя.

## Статусы

Статус запуска:

| Статус | Что значит |
| --- | --- |
| «Выполняется» | Запуск идёт. |
| «Ожидает подтверждения» | Запуск остановился на шаге «Согласование» и ждёт решения. |
| «Подтверждён» | Решения по всем действиям согласования приняты, запуск продолжается. |
| «Завершён» | Запуск закончился без ошибок. |
| «Ошибка» | Запуск остановился из-за ошибки. |
| «Отменён» | Запуск отменён. |

Статус шага в хронологии и в панели логов: «Ожидание», «Выполняется», «Успешно», «Ошибка» или
«Пропущено». «Пропущено» получают шаги, до которых запуск не дошёл: например, ветка условия,
которая не выбрана.

## Ошибки и что делать

- «Достигнут месячный лимит запусков. Обновите тариф или дождитесь его сброса.» — запуски за этот
  месяц закончились. Лимит обновляется раз в месяц, в день начала подписки; чтобы запускать
  больше, повысьте тариф. Отладочные запуски («Выполнить отсюда») лимит не расходуют.
- «Не удалось запустить воркфлоу» — запуск не начался. Повторите попытку.
- «Не удалось выполнить шаг» и «Узел не настроен: заполните обязательные поля перед запуском» —
  откройте настройки шага и заполните обязательные поля.
- «Шаг столкнулся с временной ошибкой — обновляем запуск.» — на странице запуска; Палитра сама
  загрузит актуальное состояние.
- «Не удалось загрузить воркфлоу», «Не удалось загрузить историю запусков», «Не удалось загрузить
  запуск» — нажмите «Повторить».
- «Не удалось удалить воркфлоу» — повторите попытку позже.

В установке BYOC кнопка «Новый воркфлоу» и пункт «Запустить» в списке недоступны, если лицензия
Палитры перешла в режим только для чтения или приостановлена.

## Удалить воркфлоу

1. На вкладке «Воркфлоу» откройте меню «Действия» в строке воркфлоу.
2. Выберите «Удалить».
3. В окне «Удалить «название»?» нажмите «Удалить».

В окне предупреждение: «Воркфлоу и история его запусков будут удалены безвозвратно. Запуски по
расписанию и событиям остановятся немедленно. Это действие нельзя отменить.» Если всё прошло
успешно, появится «Воркфлоу удалён».
