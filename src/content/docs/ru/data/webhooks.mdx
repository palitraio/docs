Экран «Вебхуки и API» нужен, чтобы принимать события из систем, для которых в Палитре нет
отдельного коннектора: CRM, колл-трекинга, интернет-магазина, своих сервисов. Внешняя система
отправляет события POST-запросом на адрес проекта, а Палитра записывает их в данные проекта.

Есть два способа:

- «Вебхук» — по одному событию в запросе, удобно для отправки в момент события.
- «Batch API» — до 10 000 событий в одном запросе, удобно для выгрузок пачками.

Оба способа используют один ingest API-ключ проекта.

Приём через вебхуки доступен на тарифе Pro. На тарифе без этой функции вместо экрана будет
«Приём через вебхуки не входит в ваш тариф» и кнопка «Повысить тариф».

Настраивать вебхуки могут менеджеры проекта, а также владелец и администратор организации. Для
других участников проекта экран не загрузится: вы увидите «Не удалось загрузить конфигурацию
вебхука».

## Как открыть экран

1. В боковой панели выберите проект и перейдите в раздел «Данные» — откроется «Пайплайн данных».
2. В блоке «Источники данных» найдите карточку «Вебхуки» и нажмите «Настроить» (если ключа ещё
   нет) или «Управление».

На карточке «Вебхуки» виден статус приёма и число событий за сегодня, время последнего события
или число ошибок за 24 часа.

## Создать API-ключ

Пока ключа нет, на экране блок «Ключ ещё не создан».

1. Нажмите «Сгенерировать API-ключ».
2. Появится «API-ключ создан. Скопируйте его сейчас — повторно показан не будет.»
3. В поле «Ingest API-ключ (Authorization: Bearer)» нажмите значок копирования и сохраните ключ в
   надёжном месте — например, в настройках внешней системы.

Полный ключ виден только сразу после создания. Когда вы уйдёте с экрана, в поле останется только
начало ключа с многоточием: «Полный ключ виден только один раз после перегенерации.» Если ключ
потерян, создайте новый (см. ниже).

## Настроить внешнюю систему: вебхук

На вкладке «Вебхук» в блоке «Эндпоинт вебхука»:

1. Скопируйте «URL вебхука» кнопкой рядом с полем.
2. В настройках внешней системы укажите этот адрес, метод `POST` и заголовки:
   - `Authorization: Bearer <ваш ключ>`;
   - `Content-Type: application/json`.
3. Настройте тело запроса — одно событие в формате JSON.

Пример из блока «Пример payload'а»:

```json
{
  "event_name": "purchase",
  "timestamp": "2026-05-21T10:00:00Z",
  "user_id": "user_482",
  "value": 12500.00,
  "currency": "RUB",
  "transaction_id": "ORD-4821"
}
```

### Поля события

Обязательное поле одно — `event_name`, название события (до 128 символов). Остальные можно не
передавать:

| Поле | Что это |
| --- | --- |
| `timestamp` | Время события в формате ISO 8601. |
| `user_id` | ID пользователя в вашей системе. |
| `palitra_id`, `session_id` | ID посетителя и сессии от [тега Палитры](/data/pixel/), если они у вас есть. |
| `value`, `currency` | Сумма (не меньше 0) и код валюты из трёх букв, например `RUB`. |
| `transaction_id`, `lead_id` | Номер заказа или заявки. |
| `items` | Товары в событии. |
| `properties` | Любые дополнительные параметры. |

Поля, которых нет в этом списке и в примере, Палитра не примет: запрос с неизвестным полем
отклоняется. Дополнительные данные передавайте внутри `properties`.

Чтобы Палитра считала событие конверсией, отметьте его так в реестре [событий](/data/events/).

## Настроить внешнюю систему: Batch API

На вкладке «Batch API» в блоке «Эндпоинт Batch API»:

1. Скопируйте «API endpoint».
2. Отправляйте `POST` на этот адрес с теми же заголовками `Authorization` и `Content-Type`.
3. Положите события в массив `events` — до 10 000 записей за запрос.

```json
{
  "events": [
    { "event_name": "purchase", "timestamp": "2026-05-21T10:00:00Z", "user_id": "user_482", "value": 12500 },
    { "event_name": "form_submit", "timestamp": "2026-05-21T10:01:00Z", "user_id": "user_1093" }
  ]
}
```

Пачка принимается целиком или не принимается вовсе: если хотя бы одна запись неверна, Палитра
отклонит весь запрос.

## Отправить тестовое событие

На вкладке «Вебхук» нажмите «Отправить тестовое событие». Палитра проведёт тестовое событие
`test_event` через весь путь обработки и сообщит результат:

- «Тестовое событие доставлено.» — приём работает.
- «Тестовое событие не доставлено.» — повторите попытку позже.

## Посмотреть последние события

Блок «Последние события» на вкладке «Вебхук» показывает недавние входящие события — и пришедшие
через вебхук, и через Batch API. Колонки:
«Событие», «Время», «Пользователь», «Выручка» и «Статус». Нажмите «Обновить», чтобы загрузить
свежие строки.

| Статус события | Что значит |
| --- | --- |
| «Получено» | Событие принято и ждёт обработки. |
| «Обработано» | Событие обработано. |
| «Ошибка» | При обработке события произошла ошибка. |

Если событий ещё не было, в блоке написано «Событий вебхука пока нет.».

## Статус приёма

Статус в правом верхнем углу экрана обновляется сам раз в 30 секунд.

| Статус | Что значит |
| --- | --- |
| «Получаем» | Последнее событие пришло не позже чем 15 минут назад. |
| «Сбои» | События приходят, но больше половины из них за последние 24 часа — с ошибкой. |
| «Тишина» | События приходили раньше, но за последние 15 минут — ни одного. |
| «Данных нет» | Событий ещё не было. |

При статусе «Сбои» посмотрите в «Последних событиях», какие события получили статус «Ошибка», и
проверьте их формат по таблице полей выше.

## Перегенерировать ключ

Делайте это, если ключ потерян или мог попасть к посторонним.

1. На вкладке «Вебхук» нажмите «Перегенерировать ключ».
2. Появится «Ключ обновлён. Скопируйте его сейчас — повторно показан не будет.» Скопируйте новый
   ключ из поля.
3. Замените ключ во всех внешних системах, которые отправляют события в проект.

Старый ключ сразу перестаёт работать. Тот же ключ проекта используют и вебхуки коннекторов —
обновите его и там. Над кнопками видна дата смены: «Последняя ротация: …».

## Ошибки

- «Не удалось создать ключ. Попробуйте ещё раз.» или «Не удалось перегенерировать ключ.
  Попробуйте ещё раз.» — повторите попытку. Если ошибка не уходит, проверьте, что у вас роль
  менеджера проекта или выше.
- «Не удалось загрузить конфигурацию вебхука» — нажмите «Повторить». Эту же ошибку видят
  участники без прав менеджера.
- «Не удалось загрузить статус» рядом со статусом — нажмите «Повторить».
